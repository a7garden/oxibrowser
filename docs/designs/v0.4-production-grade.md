# OxiBrowser v0.4.0 Design: Production-Grade Headless Browser

> Date: 2025-05-13
> Status: Design Document
> Scope: Polish, robustness, real-world compatibility

## Executive Summary

OxiBrowser v0.3 delivered a functional headless browser with:
- **Web APIs**: `window`, `document.body/head`, `fetch()`, `localStorage`, `atob/btoa`, `URL`, `URLSearchParams`, `crypto.getRandomValues`, `TextEncoder/TextDecoder`, `EventTarget`
- **CDP**: Network cookie CRUD, Fetch domain, Input domain
- **201 tests pass** (151 core + 22 E2E + 18 webapi + 10 event)

v0.4 focuses on **real-world compatibility** — making actual websites work, not just passing unit tests. The goal: navigate to a real website, run its JavaScript, extract content.

## Current Pain Points

### 1. fetch() Returns Sync Response — No `.text()`/`.json()`
```
// This works in browsers but fails in OxiBrowser:
const resp = await fetch('/api/data');
const data = await resp.json(); // ❌ resp is a plain object, not a real Response
```

### 2. No `document.createElement` DOM Mutation
```
// SPA frameworks do this:
const div = document.createElement('div');  // ❌ returns undefined
div.className = 'app-root';
document.body.appendChild(div);             // ❌ noop
```

### 3. Clippy Warnings (~40+)
38 warnings in oxibrowser-core alone. Code quality signal.

### 4. No Real-World E2E Tests
All E2E tests use internal CDP protocol. No test verifies "load real website → JS runs → content visible".

### 5. `Promise` Support is Limited
boa_engine's Promise microtask queue integration is incomplete. `async/await` works but chained `.then()` may not resolve.

### 6. `document.write()` Not Implemented
Some legacy scripts still use `document.write()`.

### 7. No `XMLHttpRequest`
Some older libraries and analytics scripts still use XHR.

## v0.4 Roadmap

### P0: DOM Mutation (createElement, appendChild, removeChild)
**~600 LOC | Priority: Critical**

Real DOM mutation is the #1 blocker for SPA rendering. Without it, React/Vue/Angular apps show blank pages.

**Implementation:**
1. `document.createElement(tagName)` — Create a new `DomNode` in the `DomSnapshot`, assign a `NodeId`
2. `element.appendChild(child)` — Record `DomMutation::AppendChild`, update JS-visible tree
3. `element.removeChild(child)` — Record `DomMutation::RemoveChild`
4. `document.createTextNode(text)` — Create text node
5. `element.innerHTML = ...` (write side) — Parse HTML fragment, replace children

**Key insight:** The JS thread already has access to `DomSnapshot` (via `Arc<RwLock<DomSnapshot>>`). Mutations can be applied immediately in the JS thread, then recorded as `DomMutation` for post-eval Rust-side Tree sync.

**Files:**
- `crates/oxibrowser-core/src/js/runtime.rs` — createElement, appendChild, removeChild implementations
- `crates/oxibrowser-core/src/js/dom_snapshot.rs` — DomSnapshot mutation methods
- `crates/oxibrowser-webapi/src/dom/tree.rs` — Tree::append_child, Tree::remove_child

### P1: Real `Response` Object with `.text()`/`.json()`
**~200 LOC | Priority: High**

`fetch()` currently returns a plain JS object. Need a proper `Response` class with async methods.

**Implementation:**
1. `fetch()` returns a `Promise<Response>`
2. `Response` class with:
   - `.status`, `.ok`, `.statusText`, `.headers` (sync getters)
   - `.text()` → `Promise<string>`
   - `.json()` → `Promise<object>`
   - `.arrayBuffer()` → `Promise<ArrayBuffer>`
3. The channel-based fetch bridge returns full response data (headers, body, status)

### P2: Clippy Cleanup + Error Handling
**~100 LOC changes | Priority: Medium**

- Fix 40+ clippy warnings across workspace
- Replace `unwrap()` with proper error propagation in remaining locations
- Add `#[allow(dead_code)]` where appropriate or remove dead code

### P3: `XMLHttpRequest` Basic Implementation
**~300 LOC | Priority: Medium**

Many analytics/tracking scripts still use XHR. Basic implementation:

```
new XMLHttpRequest()
  .open(method, url, async)
  .setRequestHeader(name, value)
  .send(body)
  → onload/onerror/onreadystatechange callbacks
  → .status, .responseText, .getResponseHeader()
```

### P4: Real-World Integration Tests
**~200 LOC | Priority: Medium**

Test with real websites:
1. `example.com` — Simple HTML, verify content extraction
2. `httpbin.org` — Test fetch(), headers, cookies
3. `info.cern.ch` — First website, basic HTML
4. A simple SPA — Test createElement + DOM mutation

### P5: CSS Text Screenshot
**~800 LOC | Priority: Low (deferred from v0.3)**

DOM → text-based visual output for `Page.captureScreenshot`:
1. Simple block layout algorithm
2. Text node rendering
3. Basic box model (width, height, padding)
4. Output as PNG with bitmap font
