# v0.6: CDP Events + Performance

> [!NOTE]
> This is a design document. Implementation status is tracked at the bottom.

## Goal

Complete the CDP event pipeline so external clients (Puppeteer/Playwright) receive real-time browser events. Add micro-benchmarks to ensure runtime latency stays under 50ms.

## Motivation

Currently, `console.log()` output is captured into `JsRuntime.console_output` buffer and only sent via CDP `Runtime.consoleAPICalled` when the user calls `Runtime.evaluate`. Events that happen between evaluations (e.g., `setTimeout` callbacks, `fetch` responses, XHR completion) don't emit CDP events — the external client never knows they happened.

Similarly, `MutationObserver` callbacks fire but aren't forwarded to CDP, so Puppeteer scripts that rely on `mutationObserver.observe(node, { childList: true }).then(...)` never get notified.

## Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                    JsRuntime (boa ctx)                       │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐ │
│  │ fetch()     │  │ setTimeout  │  │ MutationObserver    │ │
│  │ ─► Promise  │  │ ─► timer    │  │ ─► callback fn      │ │
│  └──────┬──────┘  └──────┬──────┘  └──────────┬──────────┘ │
│         │                │                    │            │
│         ▼                ▼                    ▼            │
│  ┌──────────────────────────────────────────────────────┐  │
│  │ EventBus (tokio mpsc channel)                       │  │
│  │  - ConsoleLog { level, args }                       │  │
│  │  - FetchComplete { request_id, response_json }      │  │
│  │  - TimerFired { timer_id }                         │  │
│  │  - MutationObserved { mutations }                  │  │
│  └─────────────────────────┬────────────────────────────┘  │
└────────────────────────────┼───────────────────────────────┘

                             ▼

└─────────────────────────────────────────────────────────────┘
```

## Implementation Plan

### 1. EventBus: unified event channel from JsRuntime → CDP

Add `EventBus` enum in `oxibrowser-core/src/js/event_bus.rs`:

```rust
/// Events emitted by JsRuntime that need to reach CDP sessions.
#[derive(Debug, Clone)]
pub enum JsEvent {
    Console { level: ConsoleLevel, args: Vec<serde_json::Value> },
    FetchComplete { request_id: String, status: u16, body: String, headers: HashMap<String, String> },
    TimerFired { timer_id: u64 },
    MutationObserved { callback_id: String, records: Vec<serde_json::Value> },
}

#[derive(Debug, Clone, Copy)]
pub enum ConsoleLevel { Log, Warn, Error, Info, Debug }

/// Shared channel sender. JsRuntime holds the sender; Browser holds the receiver.
pub type EventBusSender = tokio::sync::mpsc::UnboundedSender<JsEvent>;
pub type EventBusReceiver = tokio::sync::mpsc::UnboundedUnboundedReceiver<JsEvent>;
```

- `JsRuntime` holds `EventBusSender`
- Browser holds `EventBusReceiver` in a background task
- On each event, forward to all active CDP sessions via their `EventSender`

### 2. console.log → Runtime.consoleAPICalled (automatic)

Current: console output is buffered and sent only on `Runtime.evaluate`.

Target: `console.log()` → immediate `Runtime.consoleAPICalled` event sent to all CDP sessions.

Implementation: After `ctx.run_jobs()` + `drain_timers()`, before returning from `evaluate()`:

```rust
// In js_thread_loop after eval:
for line in console_output.read().drain(..) {
    if let Err(e) = event_tx.send(JsEvent::Console {
        level: ConsoleLevel::Log,
        args: vec![serde_json::Value::String(line)],
    }) {
        // Log error, non-fatal
    }
}
```

### 3. fetch() → Network.requestWillBeSent / Network.responseReceived

Wire the existing fetch channel to emit CDP events:

- When request is sent: `Network.requestWillBeSent` with request details
- When response is received: `Network.responseReceived` with response details

This requires the fetch channel to carry the `requestId` to correlate request → response.

### 4. setTimeout / setInterval → Runtime.timerFired

Add timer tracking map in JsRuntime:
```rust
struct TimerEntry {
    callback: JsFunction,
    interval_ms: Option<u64>,
    repeat: bool,
}
let timers: Arc<RwLock<HashMap<u64, TimerEntry>>> = Arc::new(RwLock::new(HashMap::new()));
let next_timer_id: Arc<AtomicU64> = Arc::new(AtomicU64::new(1));
```

`setTimeout(fn, ms)` → register timer, return `timerId`.
`clearTimeout(id)` → remove timer.
Background task fires timers and emits `JsEvent::TimerFired`.

### 5. MutationObserver → CDP event forwarding

`MutationObserver.observe(target, options)` → store `{ target_node_id, options, callback }`.
When DOM mutations occur (appendChild, removeChild, etc.):
1. Record mutation in `DomMutation` list
2. Check if any `MutationObserver` should fire
3. Call the callback with `MutationRecord[]`
4. Emit `JsEvent::MutationObserved` for CDP forwarding

CDP event for MutationObserver is non-standard, but we can emit a custom event: `Page.mutationObserved` or include it in `Runtime.consoleAPICalled` as a diagnostic.

### 6. Micro-benchmarks

Add `oxibrowser-core/benches/`:

| Benchmark | Target |
|-----------|--------|
| `eval_simple_literal` | < 1ms (eval `1+1`, return Number) |
| `eval_dom_query` | < 5ms (eval `document.querySelector('div')`) |
| `eval_promise_chain` | < 10ms (eval `Promise.resolve(1).then(x=>x+1)`, return Number) |
| `navigate_simple` | < 100ms (new Session, fetch simple page) |
| `navigate_complex` | < 500ms (fetch example.com) |

Use `criterion` crate for stable benchmarks.

### 7. Promise chain extraction (low priority, known issue)

`ctx.eval("Promise.resolve(1).then(x => x + 1)")` returns a `JsValue::Object` (the Promise), not the resolved value. Even after `ctx.run_jobs()`, the eval result value is frozen at evaluation time.

**Workaround**: Use JS-side chaining with temp globals:

```rust
// Phase 1: eval the expression, store result
ctx.eval("__promise_val = (Promise.resolve(1).then(x => x + 1))");

// Phase 2: chain .then() to extract the value
ctx.eval("(async () => {
    const v = await __promise_val;
    globalThis.__promise_result = v;
})()");
ctx.run_jobs();

// Phase 3: read the global
let result = ctx.eval("__promise_result");
```

This adds ~2 extra eval calls per Promise-returning expression. Only apply when the top-level expression returns a Promise object.

## Open Questions

1. **Should MutationObserver events go to CDP?** The CDP protocol doesn't have a standard MutationObserver domain. Options: (a) `Runtime.exceptionThrown`, (b) custom `Page.mutationObserved`, (c) only fire in-JS callbacks, no CDP event.

2. **Batch events or immediate?** For `console.log` in a tight loop, should we batch events and send every N ms, or emit immediately? Immediate is simpler, batch reduces WebSocket overhead.

3. **Timer resolution?** `setTimeout(fn, 0)` should fire after current event loop tick. Use tokio `sleep(Duration::ZERO)` to yield before firing.
