## Open items (§5.3 of `docs/superpowers/specs/2026-08-10-remaining-work.md`)

### A. `window.addEventListener` is absent
**Symptom:** `window.addEventListener('load', cb)` throws `addEventListener is not a function`, while `globalThis.addEventListener('load', cb)` works.
**Root cause:** `register_window_globals` in `crates/oxibrowser-core/src/js/runtime.rs` builds `window_final` via `ObjectInitializer` without EventTarget methods. The JS bootstrap (`HIDDEN_BOOTSTRAP` around `runtime.rs:10647`) installs a JS-side `addEventListener` on `globalThis`, but `window` is a distinct object and never sees that.
**Fix (3 lines in the JS bootstrap, mirroring the `matchMedia` mirror at runtime.rs:10682):** in the bootstrap IIFE, after the `globalThis.dispatchEvent` block (~line 10667) and before the `matchMedia` block, add:
```js
if (globalThis.window) {
  globalThis.window.addEventListener = globalThis.window.addEventListener || globalThis.addEventListener;
  globalThis.window.removeEventListener = globalThis.window.removeEventListener || globalThis.removeEventListener;
  globalThis.window.dispatchEvent = globalThis.window.dispatchEvent || globalThis.dispatchEvent;
}
```
**Do NOT touch Rust** — the listener registry lives on `globalThis.__oxiWinListeners` and the `||` fallback means a future Rust stub also wins. Cleanest: only the JS mirror.
**Regression:** add `acceptance/window-add-event-listener/run.{ts,sh,mock.ts}` that navigates to a tiny mock page executing `window.addEventListener('load', () => { document.title = 'fired'; })`, waits for the load lifecycle, and asserts `document.title === 'fired'`.

### B. JS `fetch()` rejects relative URLs ("invalid URL")
**Symptom:** `fetch('/api/x')` rejects with `TypeError: Invalid URL`. Real browsers resolve against the document base URL.
**Root cause:** the `fetch` JS binding in `register_window_globals` passes the user-supplied URL directly to the HTTP bridge without resolving against `page_url`. The CDP `Page.navigate` path already does this resolution (see `populate_html` calling `Url::parse(...).join(...)`); the JS path doesn't.
**Fix:** thread `page_url` into `register_window_globals` (it already takes `page_url: &str`); capture it in a closure alongside `fetch_tx`; in the `fetch` native closure, when the supplied URL has no scheme, run `Url::parse(page_url)` and `page_url.join(&supplied_url)` before forwarding to `fetch_tx.send(...)`.
**Regression:** add a sibling fixture that issues `fetch('/items.json')` against an in-page mock origin and asserts the response resolves.

### C. `hashchange` events are not fired
**Symptom:** scripts listening for `window.addEventListener('hashchange', cb)` never observe the event; navigating `location.hash = '#foo'` from JS doesn't fire; CDP `Page.fragmentNavigated` doesn't trigger it either.
**Root cause:** the JS bootstrap registers a `popstate` firing path (`runtime.rs:10633–10646`); there is no analogous `hashchange` firing.
**Fix:** in the same bootstrap block, install a setter on `location.hash` that fires `hashchange` with old/new URL (best-effort: derive `oldURL`/`newURL` from `document.URL + old/newHash`). Also fire `hashchange` after `run_navigation_scripts` when the URL contains a fragment.
**Regression:** fixture that sets `location.hash` from JS and waits on a `hashchange` listener.
