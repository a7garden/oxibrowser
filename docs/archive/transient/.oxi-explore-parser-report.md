# Parser Architect Report — Document::parse & Fragment Parsing for innerHTML

## 1. Exact flow: HTML -> DomSink -> Document -> DomSnapshot

**Entry point:** `crates/oxibrowser-webapi/src/dom/document.rs:30-35` (`Document::parse`):

```rust
let sink = DomSink::new();
let tendril = StrTendril::from(html);
let result = parse_document(sink, html5ever::ParseOpts::default()).one(tendril);
result.into_document()
```

Three-step pipeline: `parse_document(sink, opts)` -> `.one(tendril)` (drives `TendrilSink::finish()` -> `TreeSink::finish()`) -> `into_document()` (drains the `RefCell`/`Cell`s into an owned `Document`).

**`DomSink` (webapi):** `crates/oxibrowser-webapi/src/dom/document.rs:762-995`. Interior mutability (`RefCell<HashMap<NodeId,Node>>` + `RefCell<Tree>` + `Cell<usize> next_id`) because `TreeSink` takes `&self`. Storage:

- `nodes: RefCell<HashMap<NodeId, Node>>` — the flat node map.
- `tree: RefCell<Tree>` — parent/child adjacency.
- `elem_names: RefCell<HashMap<NodeId, Box<QualName>>>` — stable-addressed `Box`es so `elem_name` can hand out `ExpandedName<'a>` over an `'a` lifetime detached from the `Ref` borrow (lines 823-844; uses a `static OnceLock` fallback for safety).
- `next_id: Cell<usize>` — monotonic allocation; the root `Document` node is `id=0` (lines 783-788).

**Key sink methods:**

- `create_element` (846-867) — `alloc_id()`, stores `Box<QualName>` in `elem_names`, inserts `NodeType::Element { tag, attributes }` into `nodes`. Attribute idempotency via `add_attrs_if_missing` (952-964).
- `append` (877-890) — text gets a freshly-allocated text node + `tree.append_child`; nodes get `tree.append_child` directly.
- `append_doctype_to_document` (908-932) — id 1 typically, parented to the document root.
- `append_before_sibling` / `append_based_on_parent_node` (892-906) — locate the parent then route through `append`.
- `mark_script_already_started` / `set_quirks_mode` / `same_node` / `parse_error` / `create_pi` / `get_template_contents` are no-op or trivial.

**Document -> DomSnapshot:** `crates/oxibrowser-core/src/js/dom_snapshot.rs:159-196` (`DomSnapshot::from_frame`). Reads `frame.document()` + `frame.url()` + `frame.extract_title()`, walks the webapi tree via `collect_nodes` (752-816).

**`NodeType` -> `DomNode` mapping (the template the fragment parser should mirror):** `dom_snapshot.rs:766-806`:

- `Document` -> `("", {}, 9u8)`
- `Element { tag, attrs }` -> `(tag.to_lowercase(), HashMap::from(attrs), 1u8)` + sets `body_id`/`head_id`
- `Text` -> `("", {}, 3u8)`
- `Comment` -> `("", {}, 8u8)`
- `Doctype` -> `("", {}, 10u8)`
- `text_content` is gathered from direct text descendants, with `data-oxi-text` taking precedence when empty (lines 786-793).

## 2. innerHTML setter — exact code, exact gap

`crates/oxibrowser-core/src/js/runtime.rs:5081-5109` (the real setter — the user's "~line 4760" hint is rough; the setter lives inside `create_element_object`, which starts at line 3830):

```rust
let inner_html_setter = unsafe {
    NativeFunction::from_closure(move |_this, args, _ctx| {
        let html = args.first().and_then(|v| v.as_string())
            .map(|s| s.to_std_string_escaped()).unwrap_or_default();
        {
            let mut dom = dom_snap_ihs.write();
            if let Some(ref mut s) = &mut *dom
                && let Some(n) = s.nodes.get_mut(&nid_ihs)
            {
                n.text_content = html.clone();   // <-- raw HTML dumped into text_content
            }
        }
        mut_ihs.write().push(DomMutation::SetInnerHtml { node_id: nid_ihs, html });
        Ok(JsValue::undefined())
    })
};
```

**The bug:** HTML is shoved into `text_content` (renders as escaped text on the next read), and a `SetInnerHtml` mutation is appended that downstream handlers have to apply to the CDP `Document`. No parsing, no new `DomNode`s, no children rebuilt. `document.write` at ~line 3349 has the same text-dump hack — same gap.

## 4. Fragment parsing API (html5ever 0.29)

`~/.cargo/registry/src/.../html5ever-0.29.1/src/driver.rs:59-93`:

```rust
pub fn parse_fragment<Sink>(sink: Sink, opts: ParseOpts,
    context_name: QualName,
    context_attrs: Vec<Attribute>) -> Parser<Sink> where Sink: TreeSink;

pub fn parse_fragment_for_element<Sink>(sink: Sink, opts: ParseOpts,
    context_element: Sink::Handle,
    form_element: Option<Sink::Handle>) -> Parser<Sink> where Sink: TreeSink;
```

Both are `TendrilSink::UTF8`, so the same `.one(StrTendril)` pattern works. **A context element is required** — `parse_document` won't do because the fragment algorithm applies foster-parenting / table-in-body rules against the context tag (`<select>`, `<table>`, `<tr>`, `<td>` all need context-aware behavior). `parse_fragment_for_element` is the better fit here: we already hold a `DomNode` handle for the destination element in the live snapshot, so we can pass it directly as the context without reconstructing its `QualName`/attrs.

## 5. Recommended change — fragment sink builds `HashMap<u32, DomNode>` directly

**Where:** new type in `oxibrowser-core/src/js/`, e.g. `fragment_parser.rs`. Mirror the `elem_names` Box-pointer trick (document.rs:823-844) so `elem_name` can satisfy `ExpandedName<'a>` over `'self`. The sink writes nodes straight into a `Vec<DomNode>` keyed by fragment-local ids; after `finish()`, remap into the live snapshot's id space, replace the target's children, and `bump_revision()`.

**Why not go through webapi's `Document::parse_fragment`:**

- `DomSink` is a **private struct** (`document.rs:762` has no `pub`); `Document::parse` returns a `Document` whose `Node`/`Tree` are *also* private (`nodes` / `tree` are private fields). Today nothing escapes `document.rs` except `Document::query_*`, `Document::get_node`, and a handful of mutators.
- Going through webapi forces a `webapi::Node` -> `DomNode` translation hop (the very conversion `collect_nodes` already does once), and we'd still need to remap ids, plus make `parse_fragment`/`into_fragment` and `DomSink` public — more surface for the same result.
- A native `HashMap<u32, DomNode>` sink on the JS thread **keeps the type we already operate on**, runs inside the existing `Arc<RwLock<Option<DomSnapshot>>>` lock window, and is testable in isolation.

**Two correctness gotchas for the eventual setter implementation:**

1. **Clear the destination's existing children first** — for each child, drop its `parent` link, remove from `snap.nodes`, and update `n.children`. Otherwise orphans pile up across repeated innerHTML writes.
2. **Id remap into the live snapshot** — the fragment parser allocates ids from `0`, which collides with the document root and every previously-allocated node. Build `HashMap<local_id, global_id>` during the sink walk, then rewrite `children`/`parent` to global ids before insertion. The codebase already has *two inconsistent* id allocators today: `createElement` uses an `atomic::AtomicU32 NEXT_NODE_ID` (static across calls), and `document.write` uses `snap.nodes.keys().max()+1` — a fragment parser that respects existing ids must thread through both, but the cleanest contract is **allocate from `snap.nodes.keys().max().unwrap_or(0)+1`** consistently inside the new sink, then `bump_revision()`.

**Correctness smoke test (pre-implementation acceptance):**

```
evaluate("document.body.innerHTML = '<p id=x><span>hi</span></p>'; \
         document.querySelector('#x').textContent")
```

must return `"hi"` after the patch. Today it returns the escaped HTML string.
